# pi-strata

Расширение для [pi-coding-agent](https://github.com/badlogic/pi-mono), которое
максимизирует переиспользование KV-кэша / prompt-caching у локальных LLM
(llama.cpp / Ollama) за счёт **иммутабельного, наращиваемого слоями контекста**.

Спецификация: [`SPEC.md`](./SPEC.md).
English version: [`README.en.md`](./README.en.md).

## Идея

Промпт агента делится на слои, где префикс **байт-стабилен** между шагами:

```text
[Layer 0] системный промпт + статичные инструкции pi-strata
  [Layer 1] /*STRATA::RESEARCH::v1*/ — отчёт исследования (задача, стек, ограничения)
    [Layer 2] /*STRATA::PLAN::v1*/   — план (TODO-лист, чекбоксы)
      [Layer 3] /*STRATA::STEP-N::v1*/ — отчёты по шагам (append-only)
        [текущее] эфемерная работа (выводы команд, логи) — сбрасывается в отчёт
```

Данные слоёв **не хранятся в файлах**: модель записывает каждую фазу между
уникальными маркерами прямо в текст ответа, а расширение вычленяет блоки
алгоритмически (regex, последний блок каждого типа побеждает). Summary после
компактизации = маркерная строка + извлечённые блоки в фиксированном порядке
(строго через `\n\n`) — она сама состоит из маркированных блоков, поэтому
следующая компактизация извлекает слои из (summary + новые сообщения) тем же
regex — идентичный префикс восстанавливается без файлов (round-trip).

Внутри префикса ничего не вставляется и не правится «на лету»: разрешённые
мутации — только (а) новый блок STEP-N (конец L3), (б) новый блок PLAN
(обновлённый чекбокс — последняя версия побеждает), (в) блок WIP (последняя
секция, удаляется после завершения шага).

## Как работает

1. `session_start` — strata-каталог сессии создаётся рядом с файлом сессии:
   `<dir>/<имя-сессии>.pi_strata/` — только для одноразовых снапшотов в
   `tmp/` (файлы **не** попадают в проект).
2. `before_agent_start` — к системному промпту дописываются статичные
   инструкции пайплайна (Layer 0): протокол маркеров, порядок действий,
   требования к самодостаточным пунктам плана.
3. Агент ведёт работу по протоколу маркеров:
   - после исследования пишет блок `/*STRATA::RESEARCH::v1*/` (стек, архитектура,
     вводные, ограничения, критерии готовности);
   - затем блок `/*STRATA::PLAN::v1*/` (TODO-лист, формат `- задача`);
   - вызывает `strata(action="advance")`; в конце хода — первая компактизация.
   - после каждого шага: только блок `/*STRATA::STEP-N::v1*/` с компактным
     отчётом → `strata(action="advance", step=N)` → компактизация. PLAN остаётся
     в исходном виде; результат каждого шага фиксируется отчётом STEP-N.
   Каждый пункт плана самодостаточен: с деталями, достаточными для выполнения
   шага после компактизации, без перечитывания контекста.
4. `session_before_compact` — компактизация strata-сессии: блоки извлекаются
   regex'ом из (прежняя summary + новые сообщения), последний блок каждого типа
   побеждает, summary = детерминированная сборка (результат `custom summary`).
   Эфемерный контекст до компактизации сохраняется в `tmp/` (`step_N_raw.md` /
   `wip_raw.md`).
5. WIP-компактизация (SPEC §5): если при сборе информации уже есть RESEARCH,
   но ещё нет PLAN, либо в середине шага осталось ≤20% контекста —
   WIP-отчёт генерируется локальной моделью (fallback — детерминированный
   дайджест) и записывается между маркерами `/*STRATA::WIP::v1*/`; хвост
   ограничен ~10000 токенов. После перехода к PLAN исследовательский WIP
   удаляется; после завершения шага WIP-блок вытесняется блоком STEP-N.
6. После компактизации следующего шага — авто-продолжение (отключается
   `PI_STRATA_AUTO_CONTINUE=0`).
7. Сессия удалена (`.jsonl` исчез — через сессионный пикер pi или вручную):
   осиротевший каталог `*.pi_strata` очищается автоматически при старте
   следующей сессии (события «сессия удалена» в pi нет, поэтому уборка
   ленивая, в `session_start`).

## Установка

```bash
pi install /path/to/pi-strata
# или локально:
cp -r pi-strata ~/.pi/agent/extensions/pi-strata
```

Зависимости: только `@earendil-works/pi-coding-agent` (peer). TypeScript
компилируется jiti в рантайме pi — сборка не нужна.

## Команды и инструменты

- инструмент `strata` (actions: `advance` / `status`); `advance` валидирует
  блоки по ветви: для плана — наличие блока PLAN, для шага — обновлённый PLAN
  с блоком STEP-N; PLAN остаётся неизменным;
- `/strata` — статус слоёв; `/strata compact` — форсированная компактизация;
  `/strata reset` — очистить каталог сессии (`tmp/`).

## Конфигурация

Приоритет по каждому параметру: **окружение > конфиг > default**.
Невалидные значения на любом уровне игнорируются (фоллбур на следующий).

### Файл: `piStrata` в settings.json pi

| Файл | Область |
| --- | --- |
| `~/.pi/agent/settings.json` | глобальный |
| `.pi/settings.json` | проект (поля переопределяют глобальные) |

```json
{
  "piStrata": {
    "keepWipTokens": 10000,
    "wipThresholdPct": 20,
    "autoContinue": true
  }
}
```

### Переменные окружения (переопределяют конфиг)

| Переменная | Поле конфига | По умолчанию | Описание |
| --- | --- | --- | --- |
| `PI_STRATA_KEEP_WIP_TOKENS` | `keepWipTokens` | `10000` | сколько контекста держать поверх WIP-отчёта |
| `PI_STRATA_WIP_THRESHOLD` | `wipThresholdPct` | `20` | порог остатка контекста (%), при котором включается WIP-компактизация |
| `PI_STRATA_AUTO_CONTINUE` | `autoContinue` | вкл | авто-продолжение следующего шага после компактизации (`0` — выкл) |
| `PI_ROOT` | — | глобальный install | путь к pi-coding-agent (только для self-test) |

Эффективные настройки видны в `strata(action="status")` / `/strata` (строка `settings: ...`).

## Структура

```text
index.ts      — регистрация событий, инструмент strata, команда /strata
compaction.ts — session_before_compact: режимы plan/step/wip/plain, WIP-LLM
strata.ts     — чистая логика: маркеры, экстракция, latest-wins, summary
                (byte-stable), round-trip, parse плана, снапшоты
check.cjs     — self-test (30 тестов)
```
